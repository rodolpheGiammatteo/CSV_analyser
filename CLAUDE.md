# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

CSV Analyser: a Windows desktop app (WPF, .NET 10) for plotting large measurement CSV files (hundreds of MB, ~150 columns), with oscilloscope-like tools. The UI is written in French and translated at run time (Paramètres → Langue; see Localization below). The previous WinForms/ZedGraph version is not part of this repository (the history starts with the WPF V1).

Planned roadmap: V1 open/plot/cursor/themes (done) → V1.1 zoom undo/redo + Paramètres window (UI size, plot text size, theme) (done) → V2a per-curve settings: name, unit, color, line, markers (done, version 2.0) → V2b multiple Y axes (auto/manual/zero-aligned), stacked plots with drag-and-drop (done, version 2.1; 2.2 adds graph titles, draggable legends, fit X/Y separately, free axis sharing across units, cursor card grouped by graph and placeable, startup drop zone) → V3 save/reload configuration (JSON "recipes" keyed by column name, reapplicable to an equivalent file) + CSV export (done, version 3.0) → V4 two-cursor measurements (mean/min/max/delta/RMS) (done, version 4.0) → V5 computed curves (formulas, filters, FFT) (done, version 5.0; 5.1 adds Y cursors, graph columns and graph management in the graphs window, searchable curve pickers; 5.2 adds projects, application-wide undo, curve order/opacity, alignment on a value, graph heights, axis bound editing by click, mouse button choice, window placement memory; 5.3 adds the interface language (English), hiding the curve list, left drag on an axis always pans it; 5.4 adds annotations — markers, highlighted zones, notes — and the 5 main peaks of the spectrum).

## Commands

```powershell
dotnet build CsvAnalyser.sln
dotnet test CsvAnalyser.sln
dotnet test tests/CsvAnalyser.Tests --filter "FullyQualifiedName~FrenchDateColumn"   # single test
dotnet run --project src/CsvAnalyser.App -- "chemin\fichier.csv"                   # open a file at startup
```

Versioning is automatic (Nerdbank.GitVersioning, enabled for every project by `Directory.Build.props`): the version is `major.minor` from `version.json` plus the number of commits since that line last changed (e.g. `1.0.7`). To start a new version, edit `"version"` in `version.json` (e.g. `"1.1"` or `"2.0"`) and commit. Builds from a branch other than `main` get a `-g<commit>` suffix. The app shows it through `AppInfo.Version` (generated `ThisAssembly` class). A shallow clone breaks the commit count, so CI must fetch full history.

The app icon is drawn in code by `tools/makeicon.cs` (same design as `src/CsvAnalyser.App/Assets/app.svg`, simplified below 40 px). Regenerate with `dotnet run tools/makeicon.cs -- <dossier>` then copy `app.ico` and `app-64.png` into `src/CsvAnalyser.App/Assets/`.

`données de test/` holds a real sample file; `CsvImporterTests.RealSampleFile_IfPresent` loads it when present.

## Architecture

- **`src/CsvAnalyser.Core`** (no UI dependency): CSV import and data model.
  - `CsvFormatDetector` guesses encoding (BOM / UTF-8 / Windows-1252), delimiter (scored by field-count consistency × numeric ratio, so `1,5;2,3` is detected as `;` + decimal `,`), decimal separator, header line after an optional preamble, an optional units row, `[unit]` in headers, and per-column kind (Numeric / Date / Text / Empty).
  - `CsvImporter` reads batches of lines and parses each batch with `Parallel.For` while the next batch is being read, writing straight into one `double[]` per column (~1 s for 400 MB). Invalid, empty and infinite values become `NaN`. Text columns are dropped and listed in `Dataset.IgnoredColumns`.
  - `TimeDetector` picks the default X axis and converts date/epoch columns **in place** to seconds relative to the first sample (`TimeInfo.Origin` keeps the absolute start).
  - `Channel.SourceName` (raw header) is the stable key for future configuration mapping; `DisplayName`/`Unit` are editable.
- **`src/CsvAnalyser.App`** (WPF + WPF-UI Fluent controls + ScottPlot 5 + CommunityToolkit.Mvvm):
  - `MainViewModel` owns the dataset, curve list, X axis choice and theme, and raises `PlotChanged` events.
  - `ChannelItemViewModel` is one curve: plotted flag plus its appearance (color with `IsColorCustom`, `CurveLine`, width, `CurveMarker`, size, `MarkerSpacing`: 0 = a marker per sample, else about one every N pixels, drawn by a separate scatter that `PlotController.PlaceSpacedMarkers` fills before each render with every k-th sample of the visible range — counted in samples, not in X, so they do not fall on one phase of a periodic signal; sorted X only); `Name`/`Unit` write through to `Channel.DisplayName`/`Unit`. It reports changes through `IChannelHost` (implemented by `MainViewModel`), which raises `PlotChange.Appearance`: the controller updates the plottables in place, so the view is kept. Theme changes recolor only curves without a custom color. `CurveSettingsWindow` (pencil on hover or right-click in the list) binds directly to the item.
  - Stacked graphs and Y axes: `MainViewModel.Graphs` (always ≥ 1, empty ones are removed) and `ChannelItemViewModel.Graph`/`OwnAxis`. `GraphLayout.Build` turns them into `GraphSpec`/`AxisSpec`: in a graph, curves of the same unit share an axis (key `unit:<unit>`) unless `ChannelItemViewModel.AxisChoice` says otherwise (`"own"` → key `curve:<source name>`, or any other axis key to share that axis whatever the units; choices from `GraphLayout.AxisChoices`); axes alternate left/right. A graph also has a title (`Name`) and a legend corner + drag offset (`LegendCorner`, `LegendOffset`; the legend is dragged in `PlotController`, anchored to the nearest corner). The cursor card shows `MainViewModel.CursorGroups` (one group per graph) and is moved between three `ContentControl` hosts (left/right/bottom) by `MainWindow.PlaceCursorCard` from `CursorPanelPlacement` (saved in settings). Per-axis auto/manual range lives in `GraphViewModel.GetAxisSettings(key)`, zero alignment in `GraphViewModel.AlignZeros` (math in Core `ZeroAlignment`, unit-tested). Curves are moved by drag-and-drop (list or cursor card → a graph, or the "Nouveau graphe" strip), handled in `MainWindow` code-behind with `PlotController.GraphIndexAt/GraphBounds`.
  - `PlotController` is the only code that touches ScottPlot. One `WpfPlot` in Multiplot mode: one subplot per graph (rows, shared X, X ticks only on the bottom one); a `PaddingMatcher` pre-render action gives all subplots the same left/right padding so data areas line up, and first re-applies zero alignment (`KeepZerosAligned`: the Y axis grabbed at mouse-down/wheel leads, the others shift keeping their span — ScottPlot resets non-grabbed axes on every drag move, so "the axis that changed" is not reliable). `Rebuild` recreates subplots, axes and plottables on structural changes and keeps X plus the Y range of axes whose curves did not change; `UpdateAppearance` updates in place when the layout signature is unchanged. It draws the snapping vertical cursor across all graphs (plus, with `ShowCursorLabels`, a value label per point, spread vertically per graph by `PlaceValueLabels` so they never overlap) and does its own NaN-aware autoscale (`FitGraphY`: manual bounds, else data in the visible X range, then zero alignment; the fit buttons and the "Ajuster" menu entries pass `fitManual`, so manual axes are fitted too and keep the bounds shown, as after a mouse zoom; a right click on a fit button is `AutoAllAxes`: every Y axis back to automatic, then fitted). ScottPlot's middle-click autoscale is removed (a middle click does nothing), its benchmark double-click disabled, its context menu replaced (French, "Réglages des axes…"). When a mouse gesture or a burst of wheel ticks (400 ms timer) ends, or after Ajuster, `Record` compares `ViewSnapshot`s and asks `MainViewModel.CommitNow` for an undo step; a manual axis then takes the bounds on screen (`KeepManualBoundsOnScreen`). A left click on an axis (no drag) opens a small editor for that end of the axis (`TryOpenAxisEditor`: a Y bound becomes a manual setting, X just sets the view). `ApplyMouseButtons` maps left/middle drag to zoom rectangle/pan from `LeftDragZooms`. Curves are created in `PlottedChannels` order (last drawn on top, `MainViewModel.MoveCurveInGraph`), with `ChannelItemViewModel.Opacity` as alpha; axes are placed by `AxisSpec.IsRight` (per-axis `AxisRangeSettings.Side`, else alternating) with an optional `Title`; zero alignment uses each axis' `AlignValue` as its reference (Core `ZeroAlignment.Align(ranges, isFixed, references)`); `ColumnsLayout` weights heights by `GraphViewModel.HeightFactor`.
  - Configurations (V3): Core `ViewConfiguration` is the JSON model (graphs, axis settings, curve settings keyed by `SourceName`, X axis, view ranges; enums stored as names, defaults omitted, NaN/infinity written as named literals; `Save` goes through `WriteAtomically`, a temporary file then a swap, also used by `AppSettings`). `MainViewModel.Configuration.cs` captures/applies it (`CaptureConfiguration`, `ApplyConfiguration(config, restoreView)`: resets every curve, rebuilds the graphs, reports missing columns), saves/opens recipe files (toolbar save-icon menu, Ctrl+S, or drop a `.json` on the window) and keeps one session per CSV path (`SessionStore`, `%APPDATA%\CsvAnalyser\sessions`, saved before opening another file and on close, restored on open when `RestoreLayout`). The view models reach the plot through `IPlotView` (implemented by `PlotController`: visible X range, axis ranges, `SetView`).
  - CSV export (V3): Core `CsvExporter` (rows `[Start, End)` + optional filter for unsorted X, NaN = empty field, optional absolute date column); `ExportWindow`/`ExportViewModel` choose range (all/visible), columns (plotted/all, X column first), separator and decimal (remembered in settings); `MainViewModel.ExportAsync` writes UTF-8 with BOM in the background with the status-bar progress.
  - Measurements (V4): `MainViewModel.Measure.cs` holds `IsMeasuring` (toolbar toggle "Mesures", Ctrl+M) and the cursor positions `MeasureA`/`MeasureB` (shown to the user as X1 and X2, beside Y1/Y2; the code and the configuration keep A/B) (X values, snapped to samples, forgotten when the file or X axis changes); `MeasureRows` (value at A and B, B − A, min, max, mean, RMS, peak-to-peak from Core `RangeStatistics`, NaN ignored) is recomputed at most every 60 ms. `PlotController` draws the lines A/B in every graph (labels above the top graph, `Axes.Top.MinimumSize` makes room), drags them with the left button (`TryStartMeasureDrag`, before the pan), and the plot menu has "Placer le curseur A/B ici". Positions are saved in configurations; the export can use the A–B range.
  - Computed curves (V5): Core `Formula` (parser compiled to per-row delegates, `[curve name]` with nested brackets, functions, comparisons, NaN-safe, evaluated with `Parallel.For`) and `SignalFilters` (moving average over a time window, first-order low/high-pass with optional zero phase, derivative, trapezoid integral, all on the time base = time column when ascending, else row number). A computed curve is a `ChannelItemViewModel` with a `Definition` (`ComputedCurveConfig`), listed first with an "ƒ"; `MainViewModel.Computed.cs` creates, edits (`ReplaceItem` keeps style/graph/plotted state, later computed curves are recomputed) and deletes them (refused while another one uses it); `ComputedCurveWindow`/`ComputedCurveViewModel` is the editor ("Calculs" toolbar menu, or right-click a curve). Configurations store the definitions and rebuild them (`RebuildComputed`) after applying names/units. Computed curves are also X axis choices ("ƒ name", `XAxisOption.IsComputed`, kept in step with `Channels` by `MainViewModel.SyncComputedXAxisOptions`, suspended while a file is loaded or `RebuildComputed` runs; an edited X curve stays the X axis, a deleted one falls back to the default). The plot refits an axis when a curve's data array changes (the axis-member key includes the array identity).
  - Spectrum (V5): Core `Spectrum.Compute` (resampling on a regular grid at the median step — the number of intervals is rounded when `span / dt` is a whole number give or take rounding, else the grid slides across the samples and smooths the high frequencies — Hann/flat-top/rectangular window, radix-2 FFT, single-sided amplitude so a sine of amplitude A peaks at A) and `SpectrumResult.Peaks(5)` (highest local maxima above 0 Hz, at least 5 bins apart, at least 1 % of the highest so window leakage is not listed; checked against a square wave, whose odd harmonics are 4/(π·n)); `SpectrumWindow` (non-modal, its own `WpfPlot`) shows the checked curves over the visible range, A–B or everything, optionally in dB, with the 5 main peaks of each curve numbered on the plot and listed on the right (click = zoom on it); opened from "Calculs" or the plot menu ("Spectre (FFT) de ce graphe…"). Its menu and axis clicks mirror the main graph (right-click an axis → that axis automatic; left click → `PlotTools.ShowBoundEditor`). Each axis is automatic until the user zooms, pans or types a bound (`NoticeUserView` compares with the limits the window last set); a manual axis is kept when an option changes, except Y when dB is switched.
  - Y cursors (5.1): `IsMeasuringY` ("Mesures Y", Ctrl+Shift+M) shows two horizontal lines Y1/Y2 on one axis of one graph (`MeasureYGraph`/`MeasureYAxisKey`, chosen in the measure panel combo `MeasureYAxisChoices` or by right-click "Placer le curseur Y1/Y2 ici"); `PlotController.UpdateMeasureYLines` recreates them (plus their name labels, moved to the right edge before each render by `PlaceMeasureYLabels`), dragged vertically like A/B.
  - Graph columns (5.1): `MainViewModel.GraphColumns` (1–4, saved in configurations); `MainViewModel.GraphCell` fills the first column top to bottom, then the next; `PlotController.ColumnsLayout` is the `IMultiplotLayout`, `MatchPaddings` matches left/right padding per column, every column bottom shows X ticks and every column top gets the A/B labels. The graphs window (`AxesWindow`, rebuilt after each change) adds/reorders/removes graphs (`MainViewModel.Graphs.cs`), moves curves between graphs, adds curves with a search picker and hides them; while it is open, `BeginGraphEditing` keeps empty graphs (`GraphViewModel.KeepWhenEmpty`).
  - `Controls/SearchPicker` is the combo box for long lists (X axis, curves in the computed-curve and graphs windows): a button plus a popup with a search box (every word must match, accents ignored, also matches the column name); `KeepSelection=False` + `Picked` makes it an action picker.
  - Undo/redo and projects (5.2): `MainViewModel.History.cs` keeps whole `ViewConfiguration` states. Every relevant `PlotChange` schedules a commit (400 ms, so typing is grouped); undo applies the previous state, through `RestoreViewOnly` when only the zoom differs, else `ApplyConfiguration` (unchanged computed curves are reused). `IsDirty` compares a signature without zoom and cursor positions; the title shows "•". A project is a configuration with `SourcePath`: `OpenProjectFileAsync` opens its CSV (or, when another file is open, offers to apply the layout to it), `TrySaveProject`/Ctrl+S, `ConfirmSaveChanges` before closing or opening another file. Opening a `.json` from Ouvrir, a drop or the command line opens it as a project. The main window saves its placement, the curve list width and hidden state (button left of Ouvrir, Ctrl+L) in `AppSettings` (the width is capped by `LimitCurveList` so the graphs keep at least 320 px and the splitter stays reachable), and caps the cursor card height (it scrolls). A left drag that starts on an axis pans that axis even when left drag zooms (`ApplyMouseButtons(leftPans: true)` for that gesture).
  - Images and recent files: `Plotting/PlotTools` renders a plot or the whole multiplot at the on-screen size on a canvas scaled by `ImageScale` (Paramètres; `Plot.ScaleFactor` would push the lower stacked graphs out of the image), copies or saves PNG/JPEG, and applies the mouse button mapping (also used by `SpectrumWindow`), and draws the background grid from Paramètres (`GridOptions`: vertical/horizontal/minor lines, pattern, width, bands; the color is a mix between the data background and the axis color set by the intensity, since light theme grays were nearly invisible on some screens; bands are translucent because ScottPlot paints them over the vertical lines). The plot menu offers "this graph" or "all graphs" when there are several. `MainViewModel.Recent.cs` keeps the last CSV files and projects (`AppSettings.RecentFiles`), shown under the clock button next to Ouvrir and on the start screen.
  - Annotations: Core `AnnotationConfig` (in `ViewConfiguration.Annotations`; kind Marker/Zone/Note, anchored to row numbers so they stay on the same samples whatever the X axis; text, color, font size, line width/style, zone opacity, optional single graph, hidden flag; `ZoneNames` gives the "zone" column of the CSV export through `ExportTextColumn`). `AnnotationViewModel` (live settings, `AnnotationSettingsWindow` binds to it) and `MainViewModel.Annotations.cs` (list, add/delete/go to/measure a zone with A–B, "Zone A–B" button of the measure panel, toolbar toggle `ShowAnnotations`). They belong to the file: restored by `ApplyConfiguration` only with `restoreView` (session, project, undo), kept when a layout is applied, cleared when another file is opened or the layout is reset; every change raises `PlotChange.Annotations` (redrawn in place, undo step). `PlotController.Annotations.cs` draws markers (vertical lines) and zones (translucent `HorizontalSpan`, in front of the curves) in every graph or one, their names at the top of the upper graph of each column stacked on rows when they would overlap (`PlaceAnnotationLabels`, pre-render), notes as a circle on the curve plus a bubble (`LabelOffsetX/Y`, a thin line joins them when apart, placed by `PlaceNoteArrows`); lines and zone edges are dragged with the left button (snapped to samples), a note's point slides along its curve while its bubble stays put, and the bubble alone is dragged anywhere; the plot menu adds them at the mouse (quick popup: text, color, "Réglages…") and edits/deletes/measures the one under the mouse; the side panel lists them (click = show, double-click = settings; its eye button shows or hides them all, `ShowAnnotations`).
  - Version and updates (Paramètres, `MainViewModel.Updates.cs`): the version (`AppInfo.Version`), a "Rechercher une mise à jour" button and a "at startup" option (`AppSettings.CheckUpdatesAtStartup`, off by default; checked quietly after `ContentRendered`, only a newer version is reported in the status bar). `Services/UpdateChecker` reads the latest GitHub release of `Repository` and compares its tag with Core `ReleaseVersion` (tested); it is not switched on yet (`IsEnabled` false: the button says it is not supported, no network access) until releases are published.
  - `SettingsWindow` binds directly to `MainViewModel` (changes apply live). `UiScale` is a `LayoutTransform` on the toolbar, side panel and status bar (not on the plot: a scaled WpfPlot would be blurry); elsewhere `Controls/UiScaling` applies it: dialogs with `UiScaling.ScaleWindow="True"` scale every child of their root grid except the `TitleBar` (WPF-UI places its button hit areas without the transform) and multiply their width, after a pause and not while the mouse button is down (the Paramètres slider), shrink back to fit the screen when they have no ScrollViewer of their own; `UiScaling.Scaled` marks the spectrum window panels; context menus get it from their style (a binding, so the style does not freeze it) and code popups through `UiScaling.Apply`; `PlotFontScale` multiplies the ScottPlot font sizes. Both are saved in `AppSettings` (`%APPDATA%\CsvAnalyser\settings.json`).
  - `PlotThemes` defines the plot themes; each one also selects the WPF-UI light or dark app theme.

## Localization

- The French text is the key. In C#, every user-facing string goes through `L.T("…")` or `L.F("… {0}", x)` (Core `Localization/L.cs`, global using in both projects); never build a sentence with `$"…"`. `StyleChoice` translates its `Label` itself, `PlotTheme.ToString()` its name. Do not translate keys stored in files (column names such as the generated "Colonne n", theme names in settings, axis keys).
- XAML keeps plain French text: `ScreenTranslator` (App `Localization/Languages.cs`) translates local string values (TextBlock text and Runs, Content, Header, ToolTip, Title, PlaceholderText, SearchPicker.Placeholder) the first time each element gets a size (`SizeChanged` class handler; `Loaded` is only raised on elements with their own handler). Bound values are never touched, so a bound text must be translated in the view model; no `StringFormat` with words in XAML.
- A language is `src/CsvAnalyser.App/Languages/<code>.json` (`code`, `name`, `strings`: French → translation; empty = French), built into the exe as an embedded resource (`Languages.<code>.json`, so a single-file publish is just the exe) and listed in Paramètres; a file in `%APPDATA%\CsvAnalyser\Languages` adds a language or replaces the built-in one with the same code; it applies at the next start ("Redémarrer maintenant" restarts on the same file). `LanguageFileTests` checks every file keeps the `{n}` placeholders. When adding UI text, add its translation to `en.json`.

## Gotchas

- ScottPlot renders in physical pixels: font sizes and line widths are multiplied by the DPI scale in `PlotController`, and mouse positions are multiplied by `DisplayScale`.
- SignalXY requires ascending X; non-monotonic X columns fall back to scatter points (always drawn as points, line settings ignored).
- The whole curve-list row is a CheckBox: a double-click just ticks twice (curve settings are the pencil, deliberately not the double-click: it was triggered by mistake); `MainWindow.OnCurvePreviewMouseDown` turns Ctrl+click into selection without ticking; Shift+click ticks and selects a range; dragging a selected curve drags the whole selection (`MoveChannelsToGraph`). The filter button beside the search box (`ShowPlottedOnly`, not saved) keeps only the ticked curves in the list; an unticked curve leaves it after the click (`RefreshPlottedFilter`). Its right-click menu acts on the selection when the clicked curve belongs to it (`MainWindow.CurvesFor`: tick/untick, shown only with several curves, duplicate, delete the computed ones; Suppr deletes the selected computed curves through `DeleteComputedCurves`, so the Ctrl+click handler gives the list the keyboard focus); computed curves show an "fx" button beside the pencil on hover (their calculation); `MainViewModel.DuplicateCurves` makes computed copies (a column becomes the formula `[column]`, a computed curve keeps its definition) named "… (copie)" with the same style and graph.
- Tooltips use our own implicit `ToolTip` style and template in `App.xaml` (the WPF-UI one is semi-transparent with pale, justified text): opaque `AppToolTipBackground`/`AppToolTipBorder` set in `MainWindow.ApplyAppTheme`, `AppMenuForeground` text, wrapped at 460 px, scaled by `UiScaling`; a tooltip with its own TextBlock style must set that foreground too. A long tooltip is better as a small grid (key in bold, description), like the curve list's.
- Avoid semi-transparent text brushes (e.g. WPF-UI `TextFillColorSecondaryBrush`): on this setup they render far too light. Use the opaque `AppSecondaryTextBrush` set in `MainWindow.ApplyAppTheme`. Mica backdrop is disabled for the same reason. The same applies to the WPF-UI disabled look (a disabled icon button is invisible, and `Opacity` does not help): the undo/redo buttons stay enabled and the `HistoryButton` style grays them with the opaque `AppDisabledTextBrush` through `Tag`; the min/max boxes of the axes window are never disabled (typing a bound switches the axis to manual), and controls that cannot apply are hidden rather than disabled. Context menus use our own implicit `ContextMenu` style and template in `App.xaml` (`AppMenuBackground`/`AppMenuForeground`); do not base it on the WPF-UI style (that fell back to the classic template, white icon gutter in dark theme). The toolbar is a `WrapPanel` (with "Paramètres" docked right), so it wraps instead of pushing buttons off; keep it short anyway. A button that opens a menu on left click must set `ContextMenu.DataContext` itself (`MainWindow.OnOpenButtonMenu`). Light grays also render paler than their value, so keep them fairly dark.
- In a WPF menu header "_" is an access key and disappears: names put in menu entries (curves, axes, annotations) go through `MenuText`, which doubles it.
- The `NU1701` warning about SkiaSharp.Views.WPF (pulled in by ScottPlot.WPF) is expected and harmless.
