# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

CSV Analyser: a Windows desktop app (WPF, .NET 10) for plotting large measurement CSV files (hundreds of MB, ~150 columns), with oscilloscope-like tools. The UI is written in French and translated at run time (Paramètres → Langue; see Localization below). The previous WinForms/ZedGraph version was removed from the tree (still in git history, commit `bbfbc2e`).

Planned roadmap: V1 open/plot/cursor/themes (done) → V1.1 zoom undo/redo + Paramètres window (UI size, plot text size, theme) (done) → V2a per-curve settings: name, unit, color, line, markers (done, version 2.0) → V2b multiple Y axes (auto/manual/zero-aligned), stacked plots with drag-and-drop (done, version 2.1; 2.2 adds graph titles, draggable legends, fit X/Y separately, free axis sharing across units, cursor card grouped by graph and placeable, startup drop zone) → V3 save/reload configuration (JSON "recipes" keyed by column name, reapplicable to an equivalent file) + CSV export (done, version 3.0) → V4 two-cursor measurements (mean/min/max/delta/RMS) (done, version 4.0) → V5 computed curves (formulas, filters, FFT) (done, version 5.0; 5.1 adds Y cursors, graph columns and graph management in the graphs window, searchable curve pickers; 5.2 adds projects, application-wide undo, curve order/opacity, alignment on a value, graph heights, axis bound editing by click, mouse button choice, window placement memory; 5.3 adds the interface language (English), hiding the curve list, left drag on an axis always pans it).

## Commands

```powershell
dotnet build CsvAnalyser.sln
dotnet test CsvAnalyser.sln
dotnet test tests/CsvAnalyser.Tests --filter "FullyQualifiedName~FrenchDateColumn"   # single test
dotnet run --project src/CsvAnalyser.App -- "chemin\fichier.csv"                   # open a file at startup
```

Versioning is automatic (Nerdbank.GitVersioning, enabled for every project by `Directory.Build.props`): the version is `major.minor` from `version.json` plus the number of commits since that line last changed (e.g. `1.0.7`). To start a new version, edit `"version"` in `version.json` (e.g. `"1.1"` or `"2.0"`) and commit. Builds from a branch other than `main` get a `-g<commit>` suffix. The app shows it through `AppInfo.Version` (generated `ThisAssembly` class). A shallow clone breaks the commit count, so CI must fetch full history.

The app icon is drawn in code by `tools/makeicon.cs` (same design as `src/CsvAnalyser.App/Assets/app.svg`, simplified below 40 px). Regenerate with `dotnet run tools/makeicon.cs -- <dossier>` then copy `app.ico` and `app-64.png` into `src/CsvAnalyser.App/Assets/`.

`données de test/` holds a real sample file; `CsvImporterTests.RealSampleFile_IfPresent` loads it when present.

## Architecture

- **`src/CsvAnalyser.Core`** (no UI dependency): CSV import and data model.
  - `CsvFormatDetector` guesses encoding (BOM / UTF-8 / Windows-1252), delimiter (scored by field-count consistency × numeric ratio, so `1,5;2,3` is detected as `;` + decimal `,`), decimal separator, header line after an optional preamble, an optional units row, `[unit]` in headers, and per-column kind (Numeric / Date / Text / Empty).
  - `CsvImporter` reads batches of lines and parses each batch with `Parallel.For` while the next batch is being read, writing straight into one `double[]` per column (~1 s for 400 MB). Invalid, empty and infinite values become `NaN`. Text columns are dropped and listed in `Dataset.IgnoredColumns`.
  - `TimeDetector` picks the default X axis and converts date/epoch columns **in place** to seconds relative to the first sample (`TimeInfo.Origin` keeps the absolute start).
  - `Channel.SourceName` (raw header) is the stable key for future configuration mapping; `DisplayName`/`Unit` are editable.
- **`src/CsvAnalyser.App`** (WPF + WPF-UI Fluent controls + ScottPlot 5 + CommunityToolkit.Mvvm):
  - `MainViewModel` owns the dataset, curve list, X axis choice and theme, and raises `PlotChanged` events.
  - `ChannelItemViewModel` is one curve: plotted flag plus its appearance (color with `IsColorCustom`, `CurveLine`, width, `CurveMarker`, size); `Name`/`Unit` write through to `Channel.DisplayName`/`Unit`. It reports changes through `IChannelHost` (implemented by `MainViewModel`), which raises `PlotChange.Appearance`: the controller updates the plottables in place, so the view is kept. Theme changes recolor only curves without a custom color. `CurveSettingsWindow` (pencil on hover or right-click in the list) binds directly to the item.
  - Stacked graphs and Y axes: `MainViewModel.Graphs` (always ≥ 1, empty ones are removed) and `ChannelItemViewModel.Graph`/`OwnAxis`. `GraphLayout.Build` turns them into `GraphSpec`/`AxisSpec`: in a graph, curves of the same unit share an axis (key `unit:<unit>`) unless `ChannelItemViewModel.AxisChoice` says otherwise (`"own"` → key `curve:<source name>`, or any other axis key to share that axis whatever the units; choices from `GraphLayout.AxisChoices`); axes alternate left/right. A graph also has a title (`Name`) and a legend corner + drag offset (`LegendCorner`, `LegendOffset`; the legend is dragged in `PlotController`, anchored to the nearest corner). The cursor card shows `MainViewModel.CursorGroups` (one group per graph) and is moved between three `ContentControl` hosts (left/right/bottom) by `MainWindow.PlaceCursorCard` from `CursorPanelPlacement` (saved in settings). Per-axis auto/manual range lives in `GraphViewModel.GetAxisSettings(key)`, zero alignment in `GraphViewModel.AlignZeros` (math in Core `ZeroAlignment`, unit-tested). Curves are moved by drag-and-drop (list or cursor card → a graph, or the "Nouveau graphe" strip), handled in `MainWindow` code-behind with `PlotController.GraphIndexAt/GraphBounds`.
  - `PlotController` is the only code that touches ScottPlot. One `WpfPlot` in Multiplot mode: one subplot per graph (rows, shared X, X ticks only on the bottom one); a `PaddingMatcher` pre-render action gives all subplots the same left/right padding so data areas line up, and first re-applies zero alignment (`KeepZerosAligned`: the Y axis grabbed at mouse-down/wheel leads, the others shift keeping their span — ScottPlot resets non-grabbed axes on every drag move, so "the axis that changed" is not reliable). `Rebuild` recreates subplots, axes and plottables on structural changes and keeps X plus the Y range of axes whose curves did not change; `UpdateAppearance` updates in place when the layout signature is unchanged. It draws the snapping vertical cursor across all graphs (plus, with `ShowCursorLabels`, a value label per point, spread vertically per graph by `PlaceValueLabels` so they never overlap) and does its own NaN-aware autoscale (`FitGraphY`: manual bounds, else data in the visible X range, then zero alignment). ScottPlot's middle-click autoscale is replaced by ours, its benchmark double-click disabled, its context menu replaced (French, "Réglages des axes…"). When a mouse gesture or a burst of wheel ticks (400 ms timer) ends, or after Ajuster, `Record` compares `ViewSnapshot`s and asks `MainViewModel.CommitNow` for an undo step; a manual axis then takes the bounds on screen (`KeepManualBoundsOnScreen`). A left click on an axis (no drag) opens a small editor for that end of the axis (`TryOpenAxisEditor`: a Y bound becomes a manual setting, X just sets the view). `ApplyMouseButtons` maps left/middle drag to zoom rectangle/pan from `LeftDragZooms`. Curves are created in `PlottedChannels` order (last drawn on top, `MainViewModel.MoveCurveInGraph`), with `ChannelItemViewModel.Opacity` as alpha; axes are placed by `AxisSpec.IsRight` (per-axis `AxisRangeSettings.Side`, else alternating) with an optional `Title`; zero alignment uses each axis' `AlignValue` as its reference (Core `ZeroAlignment.Align(ranges, isFixed, references)`); `ColumnsLayout` weights heights by `GraphViewModel.HeightFactor`.
  - Configurations (V3): Core `ViewConfiguration` is the JSON model (graphs, axis settings, curve settings keyed by `SourceName`, X axis, view ranges; enums stored as names, defaults omitted). `MainViewModel.Configuration.cs` captures/applies it (`CaptureConfiguration`, `ApplyConfiguration(config, restoreView)`: resets every curve, rebuilds the graphs, reports missing columns), saves/opens recipe files (toolbar save-icon menu, Ctrl+S, or drop a `.json` on the window) and keeps one session per CSV path (`SessionStore`, `%APPDATA%\CsvAnalyser\sessions`, saved before opening another file and on close, restored on open when `RestoreLayout`). The view models reach the plot through `IPlotView` (implemented by `PlotController`: visible X range, axis ranges, `SetView`).
  - CSV export (V3): Core `CsvExporter` (rows `[Start, End)` + optional filter for unsorted X, NaN = empty field, optional absolute date column); `ExportWindow`/`ExportViewModel` choose range (all/visible), columns (plotted/all, X column first), separator and decimal (remembered in settings); `MainViewModel.ExportAsync` writes UTF-8 with BOM in the background with the status-bar progress.
  - Measurements (V4): `MainViewModel.Measure.cs` holds `IsMeasuring` (toolbar toggle "Mesures", Ctrl+M) and the cursor positions `MeasureA`/`MeasureB` (X values, snapped to samples, forgotten when the file or X axis changes); `MeasureRows` (value at A and B, B − A, min, max, mean, RMS, peak-to-peak from Core `RangeStatistics`, NaN ignored) is recomputed at most every 60 ms. `PlotController` draws the lines A/B in every graph (labels above the top graph, `Axes.Top.MinimumSize` makes room), drags them with the left button (`TryStartMeasureDrag`, before the pan), and the plot menu has "Placer le curseur A/B ici". Positions are saved in configurations; the export can use the A–B range.
  - Computed curves (V5): Core `Formula` (parser compiled to per-row delegates, `[curve name]` with nested brackets, functions, comparisons, NaN-safe, evaluated with `Parallel.For`) and `SignalFilters` (moving average over a time window, first-order low/high-pass with optional zero phase, derivative, trapezoid integral, all on the time base = time column when ascending, else row number). A computed curve is a `ChannelItemViewModel` with a `Definition` (`ComputedCurveConfig`), listed first with an "ƒ"; `MainViewModel.Computed.cs` creates, edits (`ReplaceItem` keeps style/graph/plotted state, later computed curves are recomputed) and deletes them (refused while another one uses it); `ComputedCurveWindow`/`ComputedCurveViewModel` is the editor ("Calculs" toolbar menu, or right-click a curve). Configurations store the definitions and rebuild them (`RebuildComputed`) after applying names/units. The plot refits an axis when a curve's data array changes (the axis-member key includes the array identity).
  - Spectrum (V5): Core `Spectrum.Compute` (resampling on a regular grid at the median step, Hann/flat-top/rectangular window, radix-2 FFT, single-sided amplitude so a sine of amplitude A peaks at A); `SpectrumWindow` (non-modal, its own `WpfPlot`) shows the checked curves over the visible range, A–B or everything, optionally in dB; opened from "Calculs" or the plot menu ("Spectre (FFT) de ce graphe…").
  - Y cursors (5.1): `IsMeasuringY` ("Mesures Y", Ctrl+Shift+M) shows two horizontal lines Y1/Y2 on one axis of one graph (`MeasureYGraph`/`MeasureYAxisKey`, chosen in the measure panel combo `MeasureYAxisChoices` or by right-click "Placer le curseur Y1/Y2 ici"); `PlotController.UpdateMeasureYLines` recreates them (plus their name labels, moved to the right edge before each render by `PlaceMeasureYLabels`), dragged vertically like A/B.
  - Graph columns (5.1): `MainViewModel.GraphColumns` (1–4, saved in configurations); `MainViewModel.GraphCell` fills the first column top to bottom, then the next; `PlotController.ColumnsLayout` is the `IMultiplotLayout`, `MatchPaddings` matches left/right padding per column, every column bottom shows X ticks and every column top gets the A/B labels. The graphs window (`AxesWindow`, rebuilt after each change) adds/reorders/removes graphs (`MainViewModel.Graphs.cs`), moves curves between graphs, adds curves with a search picker and hides them; while it is open, `BeginGraphEditing` keeps empty graphs (`GraphViewModel.KeepWhenEmpty`).
  - `Controls/SearchPicker` is the combo box for long lists (X axis, curves in the computed-curve and graphs windows): a button plus a popup with a search box (every word must match, accents ignored, also matches the column name); `KeepSelection=False` + `Picked` makes it an action picker.
  - Undo/redo and projects (5.2): `MainViewModel.History.cs` keeps whole `ViewConfiguration` states. Every relevant `PlotChange` schedules a commit (400 ms, so typing is grouped); undo applies the previous state, through `RestoreViewOnly` when only the zoom differs, else `ApplyConfiguration` (unchanged computed curves are reused). `IsDirty` compares a signature without zoom and cursor positions; the title shows "•". A project is a configuration with `SourcePath`: `OpenProjectFileAsync` opens its CSV (or, when another file is open, offers to apply the layout to it), `TrySaveProject`/Ctrl+S, `ConfirmSaveChanges` before closing or opening another file. Opening a `.json` from Ouvrir, a drop or the command line opens it as a project. The main window saves its placement, the curve list width and hidden state (button left of Ouvrir, Ctrl+L) in `AppSettings`, and caps the cursor card height (it scrolls). A left drag that starts on an axis pans that axis even when left drag zooms (`ApplyMouseButtons(leftPans: true)` for that gesture).
  - `SettingsWindow` binds directly to `MainViewModel` (changes apply live). `UiScale` is a `LayoutTransform` on the toolbar, side panel and status bar (not on the plot: a scaled WpfPlot would be blurry); `PlotFontScale` multiplies the ScottPlot font sizes. Both are saved in `AppSettings` (`%APPDATA%\CsvAnalyser\settings.json`).
  - `PlotThemes` defines the plot themes; each one also selects the WPF-UI light or dark app theme.

## Localization

- The French text is the key. In C#, every user-facing string goes through `L.T("…")` or `L.F("… {0}", x)` (Core `Localization/L.cs`, global using in both projects); never build a sentence with `$"…"`. `StyleChoice` translates its `Label` itself, `PlotTheme.ToString()` its name. Do not translate keys stored in files (column names such as the generated "Colonne n", theme names in settings, axis keys).
- XAML keeps plain French text: `ScreenTranslator` (App `Localization/Languages.cs`) translates local string values (TextBlock text and Runs, Content, Header, ToolTip, Title, PlaceholderText, SearchPicker.Placeholder) the first time each element gets a size (`SizeChanged` class handler; `Loaded` is only raised on elements with their own handler). Bound values are never touched, so a bound text must be translated in the view model; no `StringFormat` with words in XAML.
- A language is `src/CsvAnalyser.App/Languages/<code>.json` (`code`, `name`, `strings`: French → translation; empty = French), copied next to the exe and listed in Paramètres; it applies at the next start ("Redémarrer maintenant" restarts on the same file). `LanguageFileTests` checks every file keeps the `{n}` placeholders. When adding UI text, add its translation to `en.json`.

## Gotchas

- ScottPlot renders in physical pixels: font sizes and line widths are multiplied by the DPI scale in `PlotController`, and mouse positions are multiplied by `DisplayScale`.
- SignalXY requires ascending X; non-monotonic X columns fall back to scatter points (always drawn as points, line settings ignored).
- The whole curve-list row is a CheckBox, so a double-click toggles the curve twice: open curve settings with the pencil or the context menu, not with double-click.
- Avoid semi-transparent text brushes (e.g. WPF-UI `TextFillColorSecondaryBrush`): on this setup they render far too light. Use the opaque `AppSecondaryTextBrush` set in `MainWindow.ApplyAppTheme`. Mica backdrop is disabled for the same reason. The same applies to the WPF-UI disabled look (a disabled icon button is invisible, and `Opacity` does not help): the undo/redo buttons stay enabled and the `HistoryButton` style grays them with the opaque `AppDisabledTextBrush` through `Tag`; the min/max boxes of the axes window are never disabled (typing a bound switches the axis to manual), and controls that cannot apply are hidden rather than disabled. Context menus use our own implicit `ContextMenu` style and template in `App.xaml` (`AppMenuBackground`/`AppMenuForeground`); do not base it on the WPF-UI style (that fell back to the classic template, white icon gutter in dark theme). The toolbar is a `WrapPanel` (with "Paramètres" docked right), so it wraps instead of pushing buttons off; keep it short anyway. A button that opens a menu on left click must set `ContextMenu.DataContext` itself (`MainWindow.OnOpenButtonMenu`). Light grays also render paler than their value, so keep them fairly dark.
- The `NU1701` warning about SkiaSharp.Views.WPF (pulled in by ScottPlot.WPF) is expected and harmless.
